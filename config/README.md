# pyRadPlan Dashboard Configuration

This directory contains the configuration system for the pyRadPlan dashboard, including an interactive setup wizard for dynamic environment-specific configurations.

## Quick Start

### First-Time Setup

Run the interactive wizard to create your configuration:

```bash
python -m config.wizard setup --environment work
```

This will:
1. Detect your current environment (hostname, IP, container status)
2. Ask for network configuration (ports, base URL)
3. Configure file paths
4. Set up database and job queue
5. Save configuration to `config/work.yaml`
6. Create `.env` file with secrets
7. Link `config/active.yaml` to your new configuration

### Switching Environments

If you have multiple environments (e.g., work and home), switch between them:

```bash
python -m config.wizard switch --environment home
```

This updates `config/active.yaml` and regenerates the `.env` file.

### List Available Environments

See all saved configurations:

```bash
python -m config.wizard list
```

### Test Current Configuration

Validate your active configuration:

```bash
python -m config.wizard test
```

This checks:
- Path existence and permissions
- Port availability
- Database connectivity
- Job queue status

## Configuration File Structure

Configurations are stored as YAML files (`{environment}.yaml`):

```yaml
environment:
  name: "work"
  location: "Unraid Work Server"

network:
  backend_host: "0.0.0.0"
  backend_port: 8000
  frontend_host: "0.0.0.0"
  frontend_port: 5173
  base_url: "http://192.168.1.100"

paths:
  patient_data: "/config/workspace/data/patients"
  results: "/config/workspace/data/results"
  temp: "/tmp/pyradplan"
  machines: "${REPO_ROOT}/pyRadPlan/data/machines"

database:
  type: "sqlite"
  path: "/config/workspace/data/pyradplan.db"

jobs:
  queue: "redis"
  redis_url: "redis://localhost:6379/0"
  max_workers: 4

auth:
  enabled: false
```

## Templates

The `templates/` directory contains pre-configured templates for common scenarios:

- **`default.yaml`** - Generic development configuration
- **`work.yaml`** - Template for work environment (Unraid)
- **`home.yaml`** - Template for home environment (Unraid)

You can copy and manually edit these templates, or use the wizard to create custom configurations.

## Environment Variables (`.env`)

The wizard generates a `.env` file at the repository root containing:

```env
ENVIRONMENT=work
BASE_URL=http://192.168.1.100
BACKEND_PORT=8000
FRONTEND_PORT=5173

PATIENT_DATA_PATH=/config/workspace/data/patients
RESULTS_PATH=/config/workspace/data/results

DB_PASSWORD=<auto-generated>
JWT_SECRET=<auto-generated>
REDIS_URL=redis://localhost:6379/0
```

**Important**: The `.env` file contains secrets and is automatically git-ignored.

## Variable Substitution

Configuration files support variable substitution:

- `${REPO_ROOT}` - Automatically replaced with the repository root path
- Environment variables can be referenced in `.env` file

## Schema Validation

Configuration files are validated against `schema.json` (JSON Schema v7).

To manually validate a configuration:

```python
import yaml
import json
from jsonschema import validate

with open('config/work.yaml') as f:
    config = yaml.safe_load(f)

with open('config/schema.json') as f:
    schema = json.load(f)

validate(config, schema)
```

## Manual Configuration

If you prefer not to use the wizard, you can:

1. Copy a template:
   ```bash
   cp config/templates/work.yaml config/myenv.yaml
   ```

2. Edit the file with your settings

3. Activate it:
   ```bash
   python -m config.wizard switch --environment myenv
   ```

## Docker Integration

The configuration system integrates with Docker Compose:

```yaml
# docker-compose.yml
services:
  backend:
    environment:
      - CONFIG_FILE=/app/config/active.yaml
    env_file:
      - .env
```

Docker containers will automatically use:
- `config/active.yaml` for application config
- `.env` for secrets and environment-specific values

## Troubleshooting

### Port already in use

If ports 8000 or 5173 are already in use:

1. Run `python -m config.wizard test` to check port availability
2. Edit your config file and change the ports
3. Re-run `python -m config.wizard switch --environment <name>`

### Paths don't exist

The wizard creates directories automatically. If you encounter permission errors:

```bash
sudo mkdir -p /config/workspace/data/patients
sudo mkdir -p /config/workspace/data/results
sudo chown -R $USER:$USER /config/workspace/data
```

### Redis connection failed

Ensure Redis is running:

```bash
docker-compose up -d redis
```

Or use in-memory queue by editing config:

```yaml
jobs:
  queue: "memory"
  max_workers: 2
```

## Security Notes

1. **Never commit `.env` files** - They contain secrets
2. **Never commit `config/active.yaml`** - It's a symlink to environment-specific config
3. **Never commit configs with real passwords** - Use environment variable references instead
4. **Restrict file permissions** on production:
   ```bash
   chmod 600 .env
   chmod 700 config/
   ```

## Advanced: Multiple Servers

If you're running on multiple Unraid servers (work/home), create separate configs:

```bash
# At work
python -m config.wizard setup --environment work

# At home
python -m config.wizard setup --environment home
```

Both configs are saved in git (without secrets), so you can:

```bash
git pull  # Get configs from other location
python -m config.wizard switch --environment home
```

The `.env` file is regenerated with new secrets for each environment.

## API

The wizard can also be used programmatically:

```python
from config.wizard import ConfigWizard

wizard = ConfigWizard()

# Auto-detect environment
env_info = wizard.detect_environment()
print(f"Running on {env_info['hostname']} at {env_info['local_ip']}")

# Load active config
with open('config/active.yaml') as f:
    config = yaml.safe_load(f)

# Access config
backend_port = config['network']['backend_port']
```
